# The lab (lab.lyubomirevtimov.com): project context

A hub of courses, each one free to download and run on your own computer (since 22 November 2026). Its first course, and so far its only one, is the troubleshooting course: a practice inference API and the tickets built around it, made on 12 November 2026 to practise for a terminal troubleshooting interview. The API copies the shape of an OpenAI-compatible API, with stand-in models (text rules, not AI) and real authentication, billing, rate-limit, latency and streaming errors. `README.md` has the details, the addresses and the commands, and `practice/README.md` is the course itself.

Background on Lyubomir (his work, boundaries and languages) is in `~/Dev/personal-blog/CLAUDE.local.md`. Draw on it, but don't copy it into files here.

## The course

- **It's a crash course for anyone learning to troubleshoot an API**, from the terminal and from code. Decided on 21 November 2026, after he passed the interview it was built for: not a course for support workers. The tickets are reports from whoever's script fails (a team, a job's owner), with no customers, companies or cities. Instead of writing a reply to a customer, the learner checks themselves against a ticket's **Explain it** questions (the cause, the general rule, a prediction). Since 22 November 2026, at his request, a question their work already answers counts as answered: the tester (`TESTER.md`) reads the work first, on this ticket and the earlier ones, and asks only about real gaps, and a ticket with none left is done without a quiz. On the same day, questions that only repeated an earlier ticket were cut: ticket 3's and ticket 6's third questions, and the "what would you tell them" half of the usage exercise's fourth. Ticket 10's "other thing teams trip over" (model names, a `404 model_not_found`) went the same way, from its job line, its third question and its hints, since ticket 2 covers it. So not every ticket has three. A new question has to teach something no earlier ticket covers.
- **Nothing off the subject** (his rule, 22 November 2026). The course is a contained one on troubleshooting an API from the terminal and from Python code: finding why a call fails and what fixes it. Background that's common IT knowledge or belongs to designing an API (why headers carry a scheme, why responses carry request ids) is padding, so it isn't asked or taught up front. A learner who lacks it will ask while working, and gets taught then. On that basis ticket 1's question on the `Authorization` scheme and ticket 8's on request ids were cut, with their model answers. Check any new question or section against this before adding it.
- **It runs locally:** the course starts with cloning the repository, `npm ci`, `npm run setup` and `npm run dev`, so each learner has their own lab, keys and log.

## Where it's going

Decided on 21 November 2026: once he has finished the course, the lab becomes a **free product** that anyone can download from GitHub and run on their own machine. He finished it on 22 November 2026, and the hub below was built the same day. It isn't deployed: the live lab is still the old single documentation page, so deploy only when he says so.

- **It's an actual free course, not a showcase dressed as one** (his words, 22 November 2026). He'll write an article on the site about building it and post about it on LinkedIn, and this is the substance behind both, so the lab's pages don't advertise themselves: they say what the course is and how to get it, plainly.
- **Learners make their own keys.** `npm run setup` (`scripts/setup.mjs`, built 21 November 2026) generates two random keys and writes `.dev.vars` (the `LAB_KEYS` JSON, practice and trial accounts) and `practice/.env`, including `LAB_BASE_URL=http://localhost:8788/v1`. It never overwrites a file, and stops if only one of the two exists. The reason: the Worker counts the rate limit per account (`account.id`), so a key published for the live lab would put every learner in one shared allowance and on one shared free-plan daily quota. Local keys also keep the course's habit that keys never go in Git.
- **The Worker in the repository is ahead of the live one.** Since 21 November 2026 it logs a failed request's error code (`"error"` in the log line), which ticket 8 relies on locally, and its header comment no longer names a company. Since 22 November it's the whole hub. None of it is deployed.
- **Harden the live lab before it's deployed as the hub.** Review the live Worker for vulnerabilities and remove them. The starting points: its keys (rotate them, since they've been in use throughout the practice and may have been pasted into chats), what anyone can do with it, abuse of the free plan's daily quota, and the response headers. The hub's pages already carry a strict Content-Security-Policy, `nosniff` and a referrer policy (`src/frame.js`); the API's responses and the static files don't yet. Nothing is decided beyond that.
- **The hub of courses** (asked for on 22 November 2026, built the same day, its design left to Claude). It inherits the main site's empty bucket (the header with his name and About, the footer) but not its home page: no crate and no sleeves. The first page lists the courses newest first, each a row like a message in an inbox (he asked for that, and was wary of calling it a card): most of the bucket's width, a blue edge on the left, the title and date on the first line, a summary and a line of facts under them. A new course goes on top and pushes the rest down. A course's page is that row opened up, the same edge down its left: what it is, what it covers (the tickets by layer, titles only, nothing that gives a cause away), how it works, how to get it (the clone commands and a link to the repository and its course README) and a link to its docs. The addresses are `/`, `/troubleshooting-an-api/`, `/troubleshooting-an-api/docs/` and the API at `/v1`, which stayed at the root because it's what the course's tools, tickets and `.env` files all use; a later course with an API of its own would get its own prefix. The README's table has the files behind each.
- **The docs page was reworked with it**, and these gaps were fixed: `stream` now has its own short section (the answer arrives in pieces as it's written, in a different format from the usual JSON body, so it starts sooner; the format itself isn't described, because ticket 9 has the learner find it), and the page says the API is compatible with OpenAI's chat completions API, which ticket 10's team quotes. The base URL is `http://localhost:8788/v1` outright, since every learner runs their own. Add any new gap in the docs here.
- **Open, for him to decide:**
    - **Whether the live lab keeps serving the API.** Learners run their own, so the live `/v1` serves only his keys. Switching it off (deleting the `LAB_KEYS` secret, or answering `/v1` with an error that points to the course page) removes most of what hardening would have to cover.

    - **Whether the hub is listed by search engines.** It's still `noindex` everywhere, which was right for a practice API and may not be for a course he wants found.
    - **Where a second course's files go.** This one's are `practice/` and `exercises/` at the top of the repository. Moving them under a folder per course is easier before people clone it, but would move his ignored work files too, so it was left until a second course exists.

## Running it

- Node.js is managed with fnm from `.nvmrc`, the same version as the site. In a non-interactive shell, such as an agent's, run `eval "$(fnm env --shell zsh)" && fnm use` before any `npm` or `npx` command.
- `npm ci` once, then `npm run dev` serves it on http://localhost:8788 (the `lab-dev` entry in `.claude/launch.json` does the same). The tools use it by default.
- **Under `wrangler dev`, a request's URL carries the live hostname** from the route in `wrangler.jsonc`, not localhost. So the Worker never builds an address from `url.origin`: redirects are relative, the API's hints name a path, and the pages name `http://localhost:8788` outright.
- The Python tools run from `practice/` in its virtual environment: `source .venv/bin/activate`. It was recreated here on 21 November 2026 from `practice/requirements.txt`, on the macOS system Python (3.9.6, which no longer gets updates). That file names `requests` and `openai` without versions, so a rebuild installs the newest ones: on 21 November that was `requests` 2.32.5 and `openai` 2.48.0 (`pip freeze` shows the rest).
- Wrangler is pinned to the site's version, and its install scripts (esbuild, workerd) are denied in `allowScripts`, as on the site.

## Deploying

- **It's its own Worker**, `lyubomirevtimov-lab`, on the subdomain lab.lyubomirevtimov.com. Nothing deploys it automatically: it changes only when `npm run deploy` (`npx wrangler deploy`) is run from this folder. It runs on the free plan with no storage.
- **The keys are a Worker secret** (`LAB_KEYS`), with local copies in `.dev.vars` and `practice/.env`, which Git ignores. Never put a key in a committed file.
- **It stays out of search results**: crawling is allowed and every response carries `X-Robots-Tag: noindex, nofollow`. This one stays on, unlike the site's. The AI crawler policy is the site's, set in Cloudflare for the whole domain.
